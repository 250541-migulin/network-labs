
Буфер 1465 байт:
MTU Ethernet      = 1500 байт
IP-заголовок      = 20 байт
UDP-заголовок     = 8 байт
Наш заголовок     = 7 байт
Полезная нагрузка = 1500 − 20 − 8 − 7 = 1465 байт

## Структура проекта и назначение файлов

| Путь | Назначение |
|------|-----------|
| `common/Config.java` | Глобальные параметры: порт, размер буфера (1465 байт), размер окна (64), таймауты, пути к файлам. Вынесено отдельно для быстрой настройки под любую сеть. |
| `common/UdpPacket.java` | Формат собственного протокола поверх UDP. Заголовок 7 байт: `Seq(2) \| ACK(2) \| Flags(1) \| Len(2)`. Методы сериализации/десериализации и `zero-copy` доступ к данным. |
| `transport/ReliableSender.java` | Отправка данных. Реализует скользящее окно, таймауты ACK, ретрансмиссию, детект обрыва сессии (>10 неудачных попыток) и расчёт битрейта. |
| `transport/ReliableReceiver.java` | Приём данных. Собирает поток в правильном порядке, шлёт кумулятивные ACK (каждые 8 пакетов), буферизует внеочередные пакеты, детектит обрыв. |
| `server/UdpServer.java` | Ядро сервера. Работает **в одном потоке** (`while(true) + receive()`). Обрабатывает команды `ECHO`, `TIME`, `CLOSE`, `UPLOAD`, `DOWNLOAD`. Ведёт лог подключений и статусов докачки. |
| `server/MainServerUdp.java` | Точка входа сервера. Инициализация сокета, вызов `start()`, graceful-завершение при `CLOSE`. |
| `client/UdpClient.java` | Клиентский CLI. Цикл ввода команд, фильтрация артефактов терминала, синхронное рукопожатие, `upload`/`download` с поддержкой флага `--force`, вывод битрейта. |
| `client/MainClientUdp.java` | Точка входа клиента. Инициализация, запуск интерактивного цикла. |
| `pom.xml` | Сборка Maven. Генерирует 4 fat-JAR (`lab1-server/client`, `lab2-server/client`), автоматически копирует их на сервер по SCP через `antrun-plugin`. |

## Как собрать и запустить

```bash
# 1. Сборка всех JAR
mvn clean package

# 2. Запуск сервера (фон)
java -jar lab2-server.jar &

# 3. Запуск клиента
java -jar lab2-client.jar
```

## 📦 Класс UdpPacket
- **Назначение**: Модель прикладного протокола поверх UDP. Инкапсулирует 7-байтовый заголовок + payload.
- **Формат**: `Seq(2) | ACK(2) | Flags(1) | Len(2) | Data(0-1465)`. Big-endian.
- **Флаги**: `DATA=0x01`, `ACK=0x02`, `CMD=0x04`, `FIN=0x08`. Битовая маска.
- **Zero-copy**: `dataUnsafe()` возвращает ссылку на внутренний массив. Используется в горячем пути для избежания копий.
- **Фабричные методы**: `cmd()`, `ack()`, `data()`, `fin()` — единственный способ создания, обеспечивают инварианты.
- **Сериализация**: `toBytes()` упаковывает в big-endian, `fromBytes()` валидирует длину и защищает от переполнения.

## 📥 Класс ReliableReceiver (ЛР-2)
- **Назначение**: Надёжный приём потока данных поверх UDP. Эмулирует транспортный уровень в userspace.
- **Ключевые механизмы**:
    - **Reordering**: TreeMap буферизирует внеочередные пакеты, записывает в поток строго по порядку.
    - **Cumulative ACK**: Один ответ на каждые 8 пакетов → оверхед ~0.06% вместо 0.48%.
    - **Drop detection**: MAX_CONSECUTIVE_DROPS=50 × 20 мс = ~1 сек до разрыва сессии.
    - **FIN handling**: Сигнал завершения передачи, корректное завершение цикла.
- **Однопоточность**: Все операции синхронны, нет `Thread`/`Executor`, соответствует ТЗ.
- **Zero-copy**: `dataUnsafe()` избегает копий в горячем пути записи.

## 📤 Класс ReliableSender (ЛР-2)
- **Назначение**: Надёжная отправка потока данных поверх UDP. Эмулирует транспортный уровень в userspace.
- **Ключевые механизмы**:
    - **Sliding Window**: Queue<Pending> размером 64 пакета. Заполнение окна без ожидания ACK → заполнение канала.
    - **Cumulative ACK processing**: Удаление всех подтверждённых пакетов из начала окна одним действием.
    - **Retransmission on timeout**: Повторная отправка при ACK_TIMEOUT_MS (50 мс), лимит 50 попыток.
    - **Drop detection**: Если самый старый пакет исчерпал попытки → `SocketTimeoutException`.
    - **FIN signaling**: Завершающий пакет после отправки всех данных.
- **Однопоточность**: Все операции синхронны, нет `Thread`/`Executor`, соответствует ТЗ.
- **Zero-copy**: `readBuf` переиспользуется, `bytes` хранятся в `Pending` для быстрой ретрансмиссии.

## 🖥️ Класс UdpServer (ЛР-2)
- **Назначение**: Ядро сервера для надёжной передачи файлов поверх UDP. Работает в одном потоке.
- **Ключевые механизмы**:
    - **Command routing**: `handleCmd()` десериализует пакет, парсит команду, делегирует обработчику.
    - **Resume support**: `lastClient + lastFile` хранят контекст сессии. При повторном запросе того же клиента → `offset = размер_файла`.
    - **Handshake coordination**: `readCmd()` ждёт ответ от конкретного клиента с таймаутом, фильтрует по адресу.
    - **Logging**: Выводит "Клиент подключился", "Докачка/Новая загрузка", битрейт — для наглядности демонстрации.
- **Однопоточность**: `while(true) + receive()` с таймаутом 50 мс. Нет `Thread`, `Executor`, `select/poll`.
- **Обработка ошибок**: `try-catch` вокруг `receive()`, локальный вывод ошибки, продолжение цикла.
