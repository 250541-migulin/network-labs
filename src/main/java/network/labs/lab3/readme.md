# Лабораторная работа №3
## Организация параллельной обработки запросов на сервере с помощью мультиплексирования

### 📌 Цель работы
Реализовать сервер, который обслуживает несколько клиентов в рамках одного потока, используя механизмы мультиплексирования (`select`, `poll`, `pselect`). Обеспечить параллельную обработку команд и передачу файлов без блокировки других клиентов.

---

### 🧠 Теоретическая часть

#### Мультиплексирование
Мультиплексирование — это механизм, позволяющий одному потоку отслеживать сразу несколько источников ввода‑вывода (сокетов). Вместо того чтобы создавать отдельный поток на каждого клиента, сервер использует системные вызовы (`select`, `poll`, `epoll`) для проверки, какие соединения готовы к чтению или записи.

**Преимущества:**
- Экономия ресурсов: один поток обслуживает десятки и сотни клиентов.
- Нет необходимости в сложной синхронизации потоков.
- Масштабируемость: легко поддерживать большое количество соединений.
- Быстрая реакция: сервер не блокируется на одном клиенте, а переключается между готовыми сокетами.

#### Асинхронная передача данных
Асинхронная передача данных означает, что операции ввода‑вывода не блокируют выполнение программы. Сервер может продолжать обслуживать других клиентов, пока один из них отправляет или получает данные.

**Преимущества асинхронного ввода‑вывода:**
- 📌 **Отсутствие блокировок** — сервер не «зависает» на одном клиенте.
- 📌 **Высокая производительность** — один поток способен обслуживать множество клиентов.
- 📌 **Интерактивность** — команды обрабатываются быстро, даже при параллельной передаче больших файлов.
- 📌 **Простота архитектуры** — меньше проблем с многопоточностью и синхронизацией.

### ⚙️ Реализация
- Независимые контексты:
    - `TcpNioContext` для TCP
    - `UdpNioContext` для UDP
- Реализованы команды:
    - `PING`, `TIME`, `ECHO <msg>`
    - `UPLOAD <file>`
    - `DOWNLOAD <file>`
    - `CLOSE`
- Симметричная реализация для TCP и UDP.
- Логи на сервере:
    - `DEBUG` — каждый блок передачи
    - `INFO` — успешное завершение операций
    - `WARN` — неожиданные ошибки/разрывы.

### 🚀 Запуск
1. Собрать проект:
```bash
   mvn clean package
```
Запустить сервер:
```bash
java -cp target/classes network.labs.lab3.server.NioServer
```

Запустить TCP‑клиент:
```bash
java -cp target/classes network.labs.lab3.client.TcpNioClient
```

Запустить UDP‑клиент:
```bash
java -cp target/classes network.labs.lab3.client.UdpNioClient
```
